## A compiler, not another wrapper framework

An API contract tells an agent how to send a request. It rarely says whether a
timed-out POST is safe to retry, whether an operation can be undone, or whether
a person must approve it.

Anvil turns the source contract plus a small reviewed manifest into one
canonical model. It generates every agent-facing surface from that model.

<PipelineDiagram />

The practical result is simple: you do not maintain a CLI, an MCP server, and a
prompt as separate integrations. One operation has one name, one schema, one
auth posture, and one set of safety rules everywhere it appears.

```bash
pnpm anvil compile examples/payments/openapi.yaml \
  --manifest examples/payments/anvil.yaml \
  --service payments \
  --out generated/payments

pnpm anvil inspect generated/payments
```

## Safe by explicit construction

Anvil does not turn uncertainty into permission.

- **Unknown mutations wait.** If idempotency or effect cannot be established,
  the operation remains `review_required` and is not callable.
- **Approval changes exposure.** Only approved operations appear in the
  generated CLI catalog and MCP tool list.
- **Retries require proof.** A mutation without a valid idempotency contract is
  never retried automatically.
- **Confirmation is executable policy.** A gated call returns a structured
  refusal with the exact missing requirements.
- **The runtime remains authoritative.** Hooks provide an earlier, friendlier
  stop; the runtime repeats the checks before network access.

Try the refusal locally:

```bash
pnpm anvil run generated/payments refunds create \
  --payment-id pay_123 \
  --amount 4200 \
  --currency usd \
  --reason duplicate_charge \
  --dry-run
```

Anvil returns `confirmation_required` before constructing or sending the
request. Add `--confirm` and an idempotency key to receive a redacted dry-run
plan.

## A workflow you can resume

<LoopDiagram />

```bash
# Discover an unfamiliar API, then stop for review.
pnpm anvil agentify path/to/spec --out generated/service

# Understand the current contract and the next safe action.
pnpm anvil status generated/service
pnpm anvil inspect generated/service
pnpm anvil assess generated/service

# After reviewed enrichment and approval, prove the bundle.
pnpm anvil certify generated/service
pnpm anvil selftest generated/service
pnpm anvil conformance generated/service
pnpm anvil simulate generated/service

# Prepare a release plan. This does not deploy.
pnpm anvil publish generated/service --env prod
```

`status` is the re-entry point. It checks source identity, generated
projections, approval state, assurance freshness, target configuration, and
release-plan state, then names the next action.

## Bring the contract you already have

Anvil supports OpenAPI 3.x, Swagger 2.0, GraphQL SDL, gRPC/proto3, SOAP/WSDL,
Google Discovery, OData v2/v4 metadata, and Postman Collection v2.x. Local
multi-file graphs are captured before compilation so generated evidence is
bound to the bytes that were actually read.

Each adapter has an explicit boundary. Postman scripts are reported, not
executed. WSDL support covers a documented XSD subset. Remote references are
recorded but not fetched during local source capture. Read
[Source format support](/anvil/guides/source-formats/) for the exact contract.

If the source of truth is an API gateway, begin with estate inventory and
triage rather than compiling arbitrary exports one at a time. See
[Import a gateway estate](/anvil/cookbooks/import-a-gateway-estate/).

## When the API contract does not exist

Legacy systems often expose their real integration boundary through deployment
descriptors, WCF configuration, queue-manager definitions, or application-server
bindings. Those files establish technical facts, but they do not establish a
safe business operation.

Anvil provides a separate offline workflow:

```bash
pnpm anvil legacy inventory ./refunds-prod-export \
  --environment prod \
  --application refund-service \
  --out refunds-prod.inventory.json
```

Inventory retains conflicting bindings instead of choosing one. A coding
harness can then propose a business-shaped operation with clear schemas,
errors, pagination, transport, completion, authorization, idempotency, and
retry decisions. Anvil assesses the proposal and requires a separate human
approval.

This release stops at a reviewed binding. It does not yet generate or run the
deployment-local Java, Windows, or broker bridge. Start with
[Understand legacy estates](/anvil/concepts/legacy-estates/), then
[build an inventory](/anvil/guides/legacy-inventory/).

## Prove the bundle you are about to ship

Anvil separates four assurance questions:

| Command | Evidence produced |
| --- | --- |
| `certify` | Static agreement between AIR and generated bytes |
| `selftest` | End-to-end behavior over the generated MCP transport |
| `conformance` | Agreement across CLI, MCP, skill, hooks, and runtime posture |
| `simulate` | Safety-matrix coverage plus injected regression detection |

The reports are bound to the current bundle hash. Change the bundle and the
evidence becomes stale. Production release planning fails closed when required
evidence is missing or stale.
