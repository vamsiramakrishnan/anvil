## One contract. Every surface.

An API specification defines transport: paths, methods, fields, and schemas.
An agent also needs operating policy: effect, risk, approval, confirmation,
idempotency, retry, and auth.

If each surface defines that policy separately, the surfaces can disagree.
Anvil records the policy once in AIR and generates every surface from AIR.

<PipelineDiagram />

The consequence is concrete. A refund cannot require confirmation in the CLI
and omit it from MCP. An unapproved operation cannot appear in one client but
remain hidden in another.

```bash
pnpm anvil compile examples/payments/openapi.yaml \
  --manifest examples/payments/anvil.yaml \
  --service payments \
  --out generated/payments

pnpm anvil status generated/payments
pnpm anvil inspect generated/payments
```

## Rules that do not change

| Condition | Result |
| --- | --- |
| Operation is not approved | It is absent from callable surfaces |
| Mutation idempotency is unproven | It is not retried automatically |
| Confirmation is missing | The call fails before execution |
| A harness hook is absent | The runtime still enforces the contract |
| Bundle bytes change | Existing assurance evidence becomes stale |
| `publish` succeeds | A release plan exists; nothing has been deployed |

These rules are executable. They are not prompt guidance.

## One operating loop

<LoopDiagram />

```bash
# Capture, compile, assess, and stop for review.
pnpm anvil agentify path/to/spec --out generated/service

# Inspect the current state and the next required action.
pnpm anvil status generated/service
pnpm anvil inspect generated/service
pnpm anvil lint generated/service

# After enrichment and approval, verify one bundle hash.
pnpm anvil certify generated/service
pnpm anvil selftest generated/service
pnpm anvil conformance generated/service
pnpm anvil simulate generated/service

# Prepare an operator plan. This does not deploy.
pnpm anvil publish generated/service --env prod
```

Run `status` when you resume a bundle or a gate fails. It reports the first
required action.

## Start from the evidence you have

| Input | Start with | Boundary |
| --- | --- | --- |
| API contract | `anvil agentify` or `anvil compile` | Can become an executable bundle after review and assurance |
| Gateway export | `anvil estate inventory` | Preserves gateway identity, policies, coordinates, and import provenance |
| Legacy deployment configuration | `anvil legacy inventory` | Produces offline evidence and reviewed bindings, not a runnable bridge |
| Existing MCP server | `anvil adopt` | Unknown tools remain conservative mutations until reviewed |

Supported contracts include OpenAPI, Swagger, GraphQL SDL, proto3, WSDL,
Google Discovery, OData metadata, and Postman collections. Parsing a format does
not imply native wire support. Read [source format support](/anvil/guides/source-formats/)
before planning around gRPC, SOAP, GraphQL subscriptions, or vendor extensions.

## Verification gates

| Command | It answers |
| --- | --- |
| `certify` | Do generated bytes agree with AIR? |
| `selftest` | Does the generated MCP surface behave correctly over local transport? |
| `conformance` | Do the generated CLI, MCP server, and skill agree? |
| `simulate` | Do safety controls hold across the generated scenario matrix? |

Every record names the bundle hash it tested. A changed bundle requires new
evidence.
