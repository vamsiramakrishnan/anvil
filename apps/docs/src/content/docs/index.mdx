## Why Anvil exists

API specs describe transport. Agents need more than transport.

A callable operation also needs answers to questions such as:

- Is this a read or a mutation?
- Can it be retried?
- Does it need confirmation?
- Which auth policy applies?
- Has someone approved it for agent use?

If the CLI, MCP server, SDK, and skill answer those questions separately, they can disagree.

Anvil records the answers once in AIR, then generates every surface from AIR.

<PipelineDiagram />

That gives you one place to review behavior. A refund cannot require confirmation in the CLI and silently omit it from MCP.

```bash
pnpm anvil compile examples/payments/openapi.yaml \
  --manifest examples/payments/anvil.yaml \
  --service payments \
  --out generated/payments

pnpm anvil status generated/payments
pnpm anvil inspect generated/payments
```

## What Anvil will not let drift

| Condition | Result |
| --- | --- |
| Operation is not approved | It is not callable |
| Mutation idempotency is unproven | It is not retried automatically |
| Required confirmation is missing | The call fails before execution |
| A harness hook is absent | Runtime policy still applies |
| Bundle bytes change | Previous assurance evidence is stale |
| `publish` succeeds | A release plan exists; nothing has been deployed |

These are runtime and build rules. They are not prompt instructions.

## The operating loop

<LoopDiagram />

```bash
# Build a candidate and stop for review.
pnpm anvil agentify path/to/spec --out generated/service

# See what is known, missing, approved, or blocked.
pnpm anvil status generated/service
pnpm anvil inspect generated/service
pnpm anvil lint generated/service

# Verify the reviewed bundle.
pnpm anvil certify generated/service
pnpm anvil selftest generated/service
pnpm anvil conformance generated/service
pnpm anvil simulate generated/service

# Produce an operator plan. This does not deploy.
pnpm anvil publish generated/service --env prod
```

When a gate fails, run `status`. It tells you the next required action.

## Start with what you have

| Input | Start with | What it means |
| --- | --- | --- |
| API contract | `anvil agentify` or `anvil compile` | Can become executable after review and assurance |
| Gateway export | `anvil estate inventory` | Keeps gateway identity, policies, coordinates, and provenance |
| Legacy deployment configuration | `anvil legacy inventory` | Produces offline evidence and reviewed bindings, not a runnable bridge |
| Existing MCP server | `anvil adopt` | Treats tools conservatively until their behavior is reviewed |

Anvil parses OpenAPI, Swagger, GraphQL SDL, proto3, WSDL, Google Discovery, OData metadata, and Postman collections.

Parsing is not the same as native wire support. Check [source format support](/anvil/guides/source-formats/) before depending on gRPC, SOAP, GraphQL subscriptions, or vendor extensions.

## Release evidence

| Command | Question |
| --- | --- |
| `certify` | Do generated files agree with AIR? |
| `selftest` | Does the generated MCP surface work over local transport? |
| `conformance` | Do the CLI, MCP server, and skill agree? |
| `simulate` | Do the safety controls hold across the generated scenarios? |

Each record is tied to one bundle hash. Change the bundle and you need new evidence.
